# Outstanding synthetic-data requirements

This is a removable fixture checklist, not a request for a new fixture framework. Reuse
`tests/common::Fixture`, existing row/image helpers, fake executables, loopback servers and
`examples/ui_acceptance.rs`. Each block can disappear once its relevant behavior tests exist;
creating files alone does not close it. Detailed fault oracles remain with their subsystem items.

## FIX-01 — Real media and intentionally malformed media

**Required:** Tiny decodable PNG/JPEG/WebP/GIF/BMP/TIFF; 1×1, square, portrait, landscape and
900×600 examples; transparent PNG/WebP; two 8×8 animation frames/pages. Include truncated bytes,
text named PNG, WebP named PNG and PNG named WebP, missing/unreadable source and corrupt cache.
Use genuinely decodable unsupported media when asserting format policy rather than corrupt-input
rejection. Explicitly decide `.tif` and sequence support instead of inferring it from a suffix.

**Done when:** Codec/upload/AI tests inspect decoded format, dimensions, distinguishing pixels and
alpha. Pure hash/lock tests may retain arbitrary bytes, clearly scoped. Compute expected hashes
from generated bytes, not assumed encoder output; Nix pins tools but seeds do not guarantee bytes
across versions. No decompression bombs; bound any malformed-header/resource test in a child.

## FIX-02 — Filesystem and content identity

**Required:** Same bytes under another name, same basename with different bytes in visible dirs,
same-size replacement, modification between discover/preview/delete/upload, and preserved original
copies for cache checks. Add spaces/Unicode, external CWD, relative/nested/overlapping roots,
in/out-of-root symlinks, dangling links, loops, substituted parents and unreadable directories.

**Done when:** Use real hashes for identity tests and explicit gates/hooks for replacements. Prove
no wrong-image provider request, unauthorized deletion or B-under-A cache entry. Run permissions
cases unprivileged and record platform-specific exclusions. Never mutate process-wide PATH or real
user paths to force failure; child-only environments and temporary roots are sufficient.

## FIX-03 — Publication and configuration state

**Required:** Empty/history/mixed phases; blank metadata and exact/substr TODO markers; pending,
successful and unknown deliveries; omitted optional collections; duplicate UUIDs; nested extension
fields; legacy hash keys in both file lists; wrong-type legacy title/URL values and recovery maps.
Pair with valid/invalid TOML, a real tags file, zero/negative/nonfinite price boundary inputs where
that parser can represent them, plural tiers/galleries, Art/Artwork collisions and removed profiles.

**Done when:** Store/workflow tests preserve order/extensions, reject invalid input before mutation,
and distinguish read compatibility from writable validity. Use raw invalid JSON/protocol text for
nonfinite tokens rather than assuming valid Store JSON can contain them. Fixture rows must be valid
for the tested path; placeholder digests are inappropriate for identity/upload integration.

## FIX-04 — Explicit clocks and historical deliveries

**Required:** Fixed epochs; DST fold/gap; exactly-at-slot now; timezone month/year boundaries;
leap day; all 52 slots occupied; manual date pins; persisted-order multi-profile allocation;
partially successful legacy history without overrides, with valid synthetic URLs.

**Done when:** Assert effective instants and Calendar projections before/after unrelated edits,
not just formatted labels. Reuse existing clock parameters; no wall-clock waits or second clock
framework. Current-time demo fixtures are not deterministic scheduling regression data.

## FIX-05 — Prompt Git repositories

**Required:** Fresh empty repo, old/new/deleted paths, duplicate basenames, exact/nearest/unknown,
unreachable blobs before and after warm-up, non-HEAD ref changes, object removal, quoted/tab/newline/
backslash paths, missing/malformed archives and malformed framing. Include a small truncation corpus
whose early matches are referenced and later matches are available.

**Done when:** Isolated Git operations cannot inherit unrelated GIT_DIR/GIT_WORK_TREE/GIT_INDEX_FILE.
Probe aging is explicit where private access permits. Assertions distinguish digest identity,
lineage paths, refresh policy and rendered authority. No real prompt archive or giant blobs.

## FIX-06 — Providers and fit/install dependencies

**Required:** Loopback port-zero endpoints recording ordered requests, with controlled success,
malformed/missing/blank/marker metadata, schema rejection, response model aliases, mixed free/paid/
nonvision/duplicate catalogue, 429/5xx, slow headers/body and unavailable local tags. Add malformed
HTTP-200 tags/pull responses, refused/failed consent and a gated fake llmfit executable.

**Done when:** Dummy credentials only; expected requests and response delivery are accounted for,
semantic errors are distinguished from fixture failure, and shared deadlines stop later requests.
A closed endpoint is suitable for asserting no call, not a substitute for a response fixture.
Accept/gate/finish waits and child cleanup are bounded; inherited provider keys never select services.

## FIX-07 — Worker protocol and browser behavior

**Required:** Drive Rust through real Python serve with an injected fake session. Cover wrong
version/IDs, duplicate/truncated/oversized/invalid UTF-8 records, EOF, stderr pressure, delayed terminal,
timeouts and before/after-commit exceptions. Shared schedule vectors include gap/fold/timezone mismatch.
Use stateful locators plus routed local HTML for acknowledged/rejected/delayed success, tag clearing,
exact gallery membership, checkbox retries and calendar/time readback.

**Done when:** Inspect actual wire payloads, session calls and terminal classification; no success
without bounded positive evidence, no resend after unknown. Deny external network. FakeSession
success and no-op page doubles do not prove effects; local DOM success does not prove live DA.

## FIX-08 — Persistence, recovery and process ownership

**Required:** Intent-only, scheduled-not-applied, applied, unknown, not-submitted, empty/orphan/invalid
receipt, conflicting terminal, pre-/post-rename failures and receipt-write interruption. Add gated
workers/checkers/image tools, stderr-filling workers and deliberately detached pipe holders only
inside watchdog-owned processes with PID witnesses.

**Done when:** Reopen/restart and inspect bytes, events, no-next-send, lock/lease release and retry
blocking. Tests kill/reap all owned processes even when assertions fail. Gates synchronize causal
windows; elapsed-time sleeps alone are not race proof. Preserve original login profiles; synthetic
cookies.sqlite/profile trees suffice for copy/containment checks.

## FIX-09 — Real native UI datasets

**Required:** Empty/history/mixed/publish/calendar/prompt-search/missing-archive/reopen scenarios;
at least 30 distinguishable thumbnails beyond one viewport; long Unicode/newline/literal-markup
metadata, long prompt panels and plural options. Include dirty, saving, provider-pending and
publish-pending states, failed saves, retry and unresolved receipt cases.

**Done when:** Actual native replay establishes focus, keyboard input, visible image identity,
scroll/resize/jump behavior, persisted edits and safe close. Reuse ui_acceptance dependency injection
and retain fake-call/state/PID evidence outside Git. Message-only tests remain useful but separate.

## FIX-10 — Safe, repeatable data-root initialization

**Evidence:** `scripts/dummy-data.sh` creates 18 real PNGs with varied dimensions, real hashes and
multiple phases, but uses current time, has no prompt archive, no other formats/fault cases and does
not configure/write the tags file required by publishing. An explicit destination is overwritten
(VER-04). It is a manual demo, not a complete isolated end-to-end fixture.

**Done when:** Use fresh roots and preserve saved state on reopen. Required JSON/TOML/tags/media/
archive dependencies are complete for each scenario, clocks explicit, and endpoints/workers injected.
Do not infer safety from fake images: production UI still selects real dependency endpoints.
The acceptance example already uses create-new publication initialization; retain those preservation
tests. Do not add broad production fake/test switches or copy real data/profile contents.
